# Frontend structure — file map

> Split out of `CLAUDE.md` to keep it under the size limit. Cross-references like "see X" name a section either in `CLAUDE.md` or in another `docs/*.md` file.

```
src/
  app.html                   — HTML template; holds global CSS reset + design tokens (loads before any JS)
  app.css                    — reference copy of design tokens (not imported anywhere)
  routes/
    +layout.svelte           — pass-through layout (no styles; fonts + reset are in app.html)
    +page.svelte             — single page managing both home and project views (~180 lines)
  lib/
    types.ts                 — shared TS interfaces: FileNode, FlatNode, MenuItem, ChannelData, Note, PatternData, Placement, FileDropDetail, FileDragOverDetail
    channelStore.svelte.ts   — Svelte 5 class-based shared state: channels, patternLength, selectedChannelId (singleton, same pattern as playbackStore.svelte.ts). Also exposes exportState()/importState()/resetToDefault() for save/undo (see "Undo/redo & saving").
    patternStore.svelte.ts   — Svelte 5 class-based shared state: patterns (`PatternData[]`, each with id/name/color/lengthBeats), selectedPatternId (+ `selectedPattern` getter), addPattern(), removePatterns(ids) (see "Renaming, recoloring, deleting & selecting patterns"). Singleton shared by Toolbar's pattern dropdown and Playlist's patterns panel so both reflect the same pattern list/selection. Also exposes exportState()/importState()/resetToDefault(). `effectiveLengths` (`Map<patternId, beats>`, `$derived.by`) is every pattern's actual Song-mode length — its own `lengthBeats` floored up to its longest channel's own content (see "Song mode" below) — memoized so `songTimeline.svelte.ts` (audio scheduling) and `PlaylistTrackRow.svelte` (block width) share one content scan instead of each re-running it.
    editTools.ts              — `EditTool = 'draw' | 'delete' | 'marquee'`, the tool type shared by the Piano Roll (`PianoRollTool` is an alias) and the Playlist.
    patternActions.ts         — `deletePatterns(ids)`: deletes patterns *and* their Playlist placements (both with the deletion effect) — the cross-store wrapper around `patternStore.removePatterns()`, which can't touch `placementStore` itself.
    placementStore.svelte.ts — Svelte 5 class-based shared state: `placements` (`Placement[]`, each with id/patternId/trackId/startBeat) placed on the Playlist timeline. add()/update()/remove()/exportState()/importState()/resetToDefault(). Singleton shared by `Playlist.svelte`.
    projectSerializer.ts     — `ProjectFileData` (mirrors the Rust `ProjectFile` struct field-for-field). `serializeProject()`/`applyProjectState()` gather/apply the four stores above plus `playback.tempo`; `resetAllStores()`; `saveProject(name)`/`loadProject(name)` (invoke `save_project`/`load_project`).
    historyStore.svelte.ts   — Svelte 5 class-based singleton: undo/redo stacks (250-entry cap each), autosave toggle, debounced watcher that drives both. See "Undo/redo & saving".
    windowFocusStore.svelte.ts — Svelte 5 class-based singleton (ephemeral, not saved/undo-tracked, same treatment as `channelStore.selectedChannelId`): `order` (string[], back-to-front), `focus(id)`/`isFrontmost(id)`/`zIndexOf(id)`. Drives floating-window stacking — see "Floating windows".
    mixerStore.svelte.ts     — Svelte 5 class-based singleton (ephemeral, session-only — NOT yet wired into `projectSerializer.ts`/undo): `MASTER_TRACK_ID` (=0), `master` (`MasterChannelData`)/`channels` (`MixerChannelData[]`, id/name/volume/pan/muted/soloed/`routeTo: number[]` (multi-target)/insertSlots). `addChannel()`/`removeChannel()`/`toggleRoute()` (cycle-checked, adds or removes one edge)/`selectedChannelId`+`selectChannel()` (Master is selectable)/`selectedChannel` (routing-scoped, `channels` only)/`selectedEntity` (channel or Master, what the FX rack reads)/`routingArmed`+`toggleRoutingArmed()`/`anySoloed`/`isAudible()`. See "Mixer".
    mixerAudio.svelte.ts     — Svelte 5 class-based singleton (same `startWatching()`/`stopWatching()` + standalone `$effect.root()` pattern as `historyStore`/`playbackStore`): bridges `mixerStore`'s plain `$state` into `audioEngine`'s real per-track Web Audio nodes (volume/pan/mute-solo/routing). Started/stopped from `+page.svelte`'s `openProject`/`exitProject` alongside `historyStore`/`playback`. See "Mixer".
    hoverInfoStore.svelte.ts — Svelte 5 class-based singleton (ephemeral, session-only, same treatment as `windowFocusStore`): `name`/`value` (both `string | null`), `set(name, value?)` only — no `clear()`, since the info panel keeps showing the last-hovered control rather than reverting to an idle state. Backs the Toolbar's info panel — see "Project view" below.
    hoverInfo.ts              — `hoverInfoAction(node, { name, value? })`: the Svelte action (not `.svelte.ts` — no runes of its own, just calls into `hoverInfoStore`) that writes `hoverInfoStore` on mouseenter (and keeps it live-updated via `update()` while still hovered); mouseleave is a no-op on the store, used throughout `Dial`/`Knob`/`ScrollField`/`Slider` and the Toolbar's own controls.
    meterMath.ts              — shared dB-scaling/attack-release/color helpers (`peakOf`/`ampToFraction`/`colorForLevel`/`RELEASE`/`MIN_DB`) extracted from `PeakMeter.svelte`, also used by `PeakMeterVertical.svelte` so the toolbar's master meter and the Mixer's per-channel meters never visually diverge.
    panFormat.ts              — `formatPan(v)`: shared L##/C/R## pan display, extracted from `ChannelRow.svelte`, also used by the Mixer's per-track pan `Dial`.
    noteProps.ts             — `NoteProps` (the per-note fields the Piano Roll properties panel edits), `DEFAULT_NOTE_PROPS`, `normalizeNote()` (fills missing props on import), `soundingPitch()` (pitch + fine pitch), `formatCents()`. See "Note properties & slide notes".
    noteDefaultsStore.svelte.ts — singleton `noteDefaults.props` (ephemeral): properties newly drawn notes get (incl. current palette color + slide toggle).
    noteColorStore.svelte.ts — singleton `noteColorStore.palette` (15 hex: the Minecraft dye colors minus black; `LIME_NOTE_COLOR` = 5 is the new-note default, also Rust's `default_note_color()`), saved in `.alp` (`noteColors`) + undo-tracked.
    slideVoices.ts           — `SlideRegistry`: pure Web Audio playbackRate automation for slide notes, used by `audioEngine`.
    pianoRollZoom.svelte.ts  — Svelte 5 class-based singleton (ephemeral, session-only): `zoom` multiplier (default 1.75, clamped 0.5–4), `zoomIn()`/`zoomOut()` (×/÷ ~1.15 per step). See "Piano Roll".
    debug/                    — dev-only profiling harness (`profiler.ts`, `autoplay.ts`), inert unless the env vars in Commands › Profiling are set
    sampleName.ts             — formatSampleName(path)/formatChannelLabel(channel): shared "Drop sample" / prettified-filename label used by ChannelRow and PianoRoll. `formatChannelLabel` prefers `channel.name` (right-click > Rename, see "Channel Rack row context menu") over the sample-derived label when set.
    preferencesTypes.ts       — `Preferences`/`GeneralPrefs`/`MidiInputPrefs`/`MidiOutputPrefs` (mirror `preferences.rs` field-for-field, incl. quick-xml wrapper objects) + `default*Prefs()` factories. See "Preferences".
    preferencesStore.svelte.ts — singleton `preferences`: `general`/`inputs`/`outputs` `$state`, `load()` (app mount), `startWatching()` (debounced 500ms `save_preferences`), `inputPrefs(name)`/`outputPrefs(name)` get-or-create (call from handlers only — never from a template/derived, it mutates), `findInput`/`findOutput`, `enabledInputNames`/`enabledOutputNames`.
    preferencesUi.svelte.ts   — singleton `preferencesUi` (`open`, `tab: 'general' | 'midi'`, `show(tab?)`/`close()`), ephemeral.
    preferencesApply.svelte.ts — `startApplyingPreferences()`: `$effect.root` pushing General prefs into the systems they configure (webview zoom, `audioEngine.rebuildContext`/`setSchedulerTiming`/`setPreview`). One effect per concern.
    midi/                     — frontend MIDI system, see "MIDI": `midiParse.ts` (bytes ↔ messages, `describeMidi`), `midiProcessing.ts` (pure per-device input/output note processing), `midiStore.svelte.ts` (ports/connected/activity/log, ephemeral), `midiSystem.svelte.ts` (Rust event bridge + keeps backend connections in sync with enabled prefs), `liveNotes.svelte.ts` (held-note pipeline + `held` glow map), `qwertyKeyboard.svelte.ts` (Toolbar "typing keyboard to piano"), `midiOutput.ts` (piano-roll notes → scheduled MIDI out)
    systemAudio.ts            — singleton `systemAudio` (`start()`/`stop()`/`getAnalyser()`): the Toolbar monitor's "System audio" source — see "Toolbar audio monitor & peak meter"
    portal.ts                  — `portal(node)`: shared Svelte action that moves a node onto `<body>` so a floating overlay escapes an ancestor's `overflow: hidden`/`auto` clipping. Used by `DragTooltip.svelte`, `ChannelRow.svelte`'s own context menu, `KnobContextMenu.svelte`, and `MenuBar.svelte`'s dropdowns.
    colorUtils.ts              — hex/HSV color helpers (`hexToRgb`/`rgbToHex`/`hsvToRgb`/`rgbToHsv`/`isColorful`/`randomColorfulHex`) backing `ColorWheel.svelte` and ChannelRow's right-click "Recolor randomly". No color-picker library exists in the project — hand-rolled like every other control. `isColorful(r,g,b)` is the concrete definition of "a color" used throughout: at least one RGB channel-pair gap of 50 (0–255 range), i.e. not washed-out/near-grey.
    multisample.ts            — buildMultisample()/pickFromFolder(): turns a dropped folder's file list into a note→sample map and resolves nearest-pitch playback (see "Multisample instrument folders")
    plugins/registry.ts       — plugin registry for the sample-field menu (PluginDef: id/name/kind/assign/remove/open; PLUGINS = [Bloom]), assignPlugin/removePlugin/channelPlugin — see docs/instrument.md
    channelDrop.ts            — applyDropToChannel(ch, drop): what an explorer drop onto a channel does (`.sfz` → instrument preset, audio file/folder → sample/multisample + clears the preset). Shared by ChannelRack's insert-drop and ChannelRow's drop zone
    instrument/               — Bloom instrument (see docs/instrument.md): `types.ts` (InstrumentSettings, defaults, normalize/export), `sfz.ts` (parser), `presetLoader.ts` (cached load/list), `regionSelect.ts` (layers/round robin), `voiceShape.ts` (settings + macros → VoiceShape, presetDefaults), `hits.ts`, `voiceGraph.ts` (builds one voice), `envelope.ts`, `sourceRate.ts` (header sample rate), `channelSound.ts` (usesPreset/channelHasSound), `applyPreset.ts`, `paramScales.ts` (knob mappings), `instrumentWindow.svelte.ts` (window open state)
    channelLoop.ts            — channelLoopLength(ch, loopLength, barLength): pure function shared by audioEngine.ts and ChannelRow.svelte, finds how many steps of a channel's own content repeat before it restarts (see "Per-channel independent looping")
    pianoroll/
      pitch.ts                — pure pitch/geometry helpers shared by the piano roll components: pitch↔y, step↔x, key/black-key/C-note tests, static layout constants (KEY_COL_W, RULER_H, LANE_H), plus zoom-aware sizing: `BASE_KEY_H`/`BASE_STEP_W` (fixed 1x reference, used only by `MiniNoteRoll`'s zoom-independent Channel Rack preview) vs. `keyH()`/`stepW()`/`gridTotalH()` (functions reading the live `pianoRollZoom.zoom` — everything else in the Piano Roll goes through these). `stepToX`/`patternWidth` take an optional second `widthPerStep` arg (defaults to the live `stepW()`) so existing zero-arg call sites stay zoom-reactive automatically. parseNoteName(filename) for multisample folders
    components/
      SampleFieldMenu.svelte — ChannelRow sample field's right-click plugin menu (portalled)
      Sidebar.svelte         — home sidebar: logo, nav, settings footer
      ProjectsPanel.svelte   — projects list, search, empty state, action buttons
      NewProjectModal.svelte — new-project form modal (owns its own state + invoke)
      MenuBar.svelte         — project page menu fragment (no wrapper element): logo SVG + File/Edit/… dropdowns. Embedded inside Toolbar.svelte. Dropdowns are portalled onto `<body>` (`portal` action) at `position: fixed` (from the clicked button's rect) with `z-index: 10000` — the Toolbar's `overflow: hidden` otherwise clips them, leaving them under the file explorer.
      BlackBox.svelte        — Toolbar's audio monitor: a canvas that click-toggles between an oscilloscope and a spectrum analyzer, both read from `audioEngine.getAnalyser()`. See "Toolbar audio monitor & peak meter" below.
      PeakMeter.svelte       — Toolbar's two-bar stereo peak meter, read from `audioEngine.getStereoAnalysers()`. See "Toolbar audio monitor & peak meter" below.
      DragTooltip.svelte     — dumb/presentational "KEY: value" box. Rendered by `Dial`/`ScrollField` while `dragging` is true — see below. Takes an `anchorEl` prop and portals itself onto `<body>` (via the shared `portal` action, `src/lib/portal.ts`), positioned `position: fixed` from `anchorEl.getBoundingClientRect()` captured once at mount (via `untrack()` — intentionally non-reactive, since the anchor doesn't move mid-drag and the component only lives for one drag gesture). The portal is required, not cosmetic: `position: fixed` alone does not escape an ancestor's `overflow: hidden`/`auto` clipping if the element stays a DOM descendant of it (e.g. `ChannelRack`'s `.rack-list` or `FloatingWindow`'s own `.fw`), so without it the tooltip is invisible/cut off for any row scrolled to the top of a floating window. `z-index: 10000` — deliberately above every other z-index in the app so it's never covered.
      KnobContextMenu.svelte — tiny shared right-click menu for Dial/Knob: a single "Reset" item that sets the knob back to its `defaultValue`. Same portal/backdrop/ctx-menu shape as `ChannelRow.svelte`'s own context menu, factored into its own component (unlike the Mixer's rename widget, which is deliberately duplicated because its two contexts render differently — this one is identical in both callers, so sharing it is the right call). Props: `x`/`y` (menu position), `onReset`, `onClose`.
      Dial.svelte            — circular knob, drag-to-set (mousedown/mousemove/mouseup via `svelte:window`, left button only — `e.button !== 0` bails so right-click doesn't also start a drag). Value ranges `[0, max]` (`max` defaults to `1`). `sweepStart`/`sweepDegrees` (degrees, clockwise from top) control where the knob's travel begins/ends — default `210`/`300` is the classic full-rotation pot look (gap at the bottom); `ChannelRow`'s Volume dial overrides these to `270`/`180` (left → top → right) so 0% is on the left, 100%/unity gain lands at the top, and 200% lands on the right, rather than sweeping down through the bottom. Props include `tooltipKey` (e.g. "PAN") and `format` (value → display string, defaults to percentage) which drive a `DragTooltip` shown while dragging. **Right-click opens `KnobContextMenu`** with a "Reset" item (sets `value = defaultValue`) — a slower, more discoverable alternative to the existing double-click reset; both do the same thing.
      Knob.svelte            — same bindable-value/drag-to-set contract as Dial (mousedown guarded to the left button only). Instead of Dial's rotating indicator dot, the readout is a full 360° rim: `inactiveColor` (default neutral grey) for the empty portion, `activeColor` (default `var(--accent)`) for the filled `(value/max)*360°` arc. No `sweepStart`/`sweepDegrees`/`showArc` — there's only the one rim-style rendering. Also right-click-resets via `KnobContextMenu`, same as Dial. Currently unused (its former caller, the Mixer's `JackPort`, was removed when the Mixer's cable-patchbay routing was replaced with per-track routing — see "Mixer") but kept as a small, generic, documented primitive for whenever a full-rim knob is needed again.
      ScrollField.svelte     — rectangular numeric field, drag-to-set (same mechanics as Dial) plus mouse-wheel. `label` is an inline unit suffix (e.g. "beats"); `tooltipKey` (e.g. "LEN") is the separate drag-tooltip key shown via `DragTooltip` while dragging.
      Slider.svelte          — vertical mixer-style fader, drag-to-set. Unlike Dial's `movementY`-accumulation, drag math is an absolute delta from drag-start position mapped 1:1 against the fader's own `height` (`ScrollField`'s dragStartY/dragStartVal pattern, scaled by `height` instead of a step multiplier) — a physical fader's position should be a driftless function of pixel distance dragged, not an accumulated relative delta. `value` ranges `[min, max]` (defaults `0..2`, matching `ChannelData.volume`'s convention). Double-click resets to `defaultValue`; shows `DragTooltip` while dragging, same convention as Dial/ScrollField. Used by the Mixer's channel strips — see "Mixer".
      ColorWheel.svelte      — HSV color picker: a canvas hue/saturation wheel (full value, drawn once per resize into a cached `ImageData` then redrawn with just the ring indicator per drag tick) plus a horizontal value/brightness bar below. `value` is `$bindable` (plain hex string, no `null` — callers seed a default before mounting it, see `ChannelRow.svelte`'s `openRecolor()`). Canvas is rendered at `devicePixelRatio` resolution and redrawn via `ResizeObserver`, the same responsive-canvas pattern as `PlaylistClipWaveform.svelte`, so it fills whatever width its container gives it (`aspect-ratio: 1`). Drag mechanics deliberately use plain `mousedown`/`svelte:window mousemove`/`mouseup` (not Pointer Events) to match Dial/Slider's convention — this also matters functionally inside `ChannelRow`'s context menu, since a `pointerdown`'s `stopPropagation()` would not suppress the separate compatibility `mousedown` the browser fires afterward, which would otherwise reach the menu's backdrop and close it the instant a wheel-drag starts. Pointer position past the wheel's rim is clamped to the edge rather than ignored, so dragging never "sticks"/dead-zones. Used by ChannelRow's right-click Recolor (see "Channel Rack row context menu" below); no color-picker library exists in the project, this is hand-rolled like every other control.
      preferences/           — the Preferences modal: `PreferencesModal.svelte` (backdrop + left tab list, Esc/backdrop closes, z-index 9000), `GeneralTab.svelte`, `MidiTab.svelte` (→ `MidiDeviceList`, `MidiInputSettings` + `VelocityCurvePreview`, `MidiOutputSettings`, `MidiMonitor`), and shared form primitives `PrefSection`/`PrefRow`/`PrefSelect`/`PrefSegmented`/`PrefToggle` (numbers reuse `ScrollField`). See "Preferences".
      midi/                  — `MidiLed.svelte` (Toolbar row-2 activity light, hover shows last message), `ActivityDot.svelte` (per-device blink dot), `QwertyPiano.svelte` (no markup, window key listeners for the QWERTY keyboard; mounted in project view)
      ChannelMidiOutMenu.svelte — ChannelRow's right-click › "MIDI out…" sub-view (port list of *enabled* outputs + MIDI channel `ScrollField`)
      Toolbar.svelte         — two-row toolbar (CSS grid 2col × 2row). Row 1: menu section (slate) + transport + BPM/POS displays + feature toggles + monitor placeholder + peak meter. Row 2: info box + panel toggle buttons + snap/pattern dropdowns + Shift/Alt/Ctrl indicators. Accepts bindable props: showExplorer, showChannelRack, showPianoRoll, showPlaylist, showMixer.
      FileExplorer.svelte    — activity bar + explorer panel + file tree. Accepts `show` bindable prop; root wrapper uses display:contents / display:none to hide without unmounting.
      ExplorerResizeHandle.svelte — 5px draggable grip on `FileExplorer`'s right edge (pointer capture on the handle itself, no document listeners); binds the explorer's `width` (default 220, clamped 140–600, session-only — not saved/undo-tracked). The workspace-zone `ResizeObserver` in `+page.svelte` re-measures automatically, so maximized floating windows follow the new width.
      ProjectShortcuts.svelte — no markup, just `<svelte:window onkeydown>` for the global Ctrl/Cmd+Z (undo), Ctrl/Cmd+Y or Ctrl/Cmd+Shift+Z (redo), and Ctrl/Cmd+S (save) shortcuts; ignores keydowns targeting an `input`/`textarea`/contenteditable. Mounted once in the project view of `+page.svelte`.
      EditToolButtons.svelte — Draw/Delete/Drag-select toggle buttons (bindable `tool: EditTool`, `items` noun for tooltips), shared by the Piano Roll and Playlist headers
      FloatingWindow.svelte  — shared `position: fixed` window shell (drag/resize/maximize chrome, `header`/`children` snippets) behind Playlist/ChannelRack/PianoRoll/Mixer. Requires an `id` prop (`"channel-rack"`/`"piano-roll"`/`"playlist"`/`"mixer"`) used to look up its z-index from `windowFocusStore` — see "Floating windows".
      Playlist.svelte        — playlist grid (tracks × bars, 4/4 shading, sticky headers) plus a patterns panel docked on the left (see "Playlist patterns panel" below)
      ChannelRack.svelte     — draggable floating window for the channel rack (step sequencer), toggled from toolbar. Sources `channels`/`patternLength` from `channelStore` (not local state) so the Piano Roll can share the same data.
      PianoRoll.svelte       — draggable floating window (same chrome pattern as ChannelRack), toggled from toolbar via `showPianoRoll` and also opened by double-clicking a channel's sample name in the rack. Coordinates the sub-components below and owns tool/selection/scroll-sync state.
      pianoroll/
        PianoRollHeader.svelte — draggable title bar + Draw/Delete/Marquee tool toggle (`EditToolButtons`) + note-properties toggle + close button
        PianoKeys.svelte       — sticky-look vertical piano key column (128 keys, black/white, C-note labels), Y-scroll driven by a `scrollTop` prop via CSS transform (not native scroll)
        PianoRollRuler.svelte  — sticky-look step ruler (4-step grey/orange grouping, playhead cell), X-scroll driven by a `scrollLeft` prop via CSS transform
        NoteGrid.svelte        — the actual native-scrolling grid (only real scrollbars live here); owns all draw/select/marquee/move/resize/copy-paste/delete pointer + keyboard interaction; emits scroll position up via `onScroll`
        VelocityLane.svelte    — per-note velocity bars below the grid, drag-to-set (mirrors ChannelRow's paint gesture), X-scroll driven the same way as the ruler
        NotePropertiesPanel.svelte — left-docked panel (header toggle): 6 dials (`NotePropDial.svelte`), slide toggle, `NoteColorPalette.svelte` (5×3 swatches, right/double-click → ColorWheel popover)
      playlist/
        playlistEditor.svelte.ts — `PlaylistEditor` class (one instance per Playlist): the timeline's tool, block selection (`SvelteSet`), live move, marquee and drag-delete gestures + `deleteSelected()`/`selectAll()`/`prune()`; also exports `freeStart()`. See "Tools & block selection" under "Playlist"
        PatternsPanel.svelte   — the Playlist's left patterns panel (card list + `+`); owns the inline-rename target and the right-click menu
        PatternCard.svelte     — one card: swatch, name (inline-rename input while `renaming`), length `ScrollField`; `active` styling
        NewPatternModal.svelte — name prompt shown by the panel's `+` before a pattern is created
        PatternContextMenu.svelte — Rename pattern / Recolor / Recolor randomly / Delete pattern, same portal/backdrop/look as ChannelRow's menu
      instrument/            — Bloom window: InstrumentWindow (FloatingWindow `instrument`), PresetBrowser, InstrumentPanel, MacroRow, AmpSection, FilterSection, Section, ParamKnob (Dial over a ParamScale), EnvelopeGraph
      mixer/
        Mixer.svelte           — draggable floating window (`id="mixer"`), same chrome pattern as ChannelRack/PianoRoll but a simpler header (title/maximize/close only). Body is just Master strip | scrollable row of channel strips + "add channel" button — see "Mixer"
        MixerChannelStrip.svelte — one boxed strip (Master or a numbered channel), top to bottom: label (double-click to rename, channel only; + remove "×", channel only), pan `Dial` (channel only), `PeakMeterVertical` + `Slider` bound to `data.volume`, `MixerMuteSolo` (channel only), `MixerRoutePoint` (arrow if this is `mixerStore.selectedChannelId` and it's a channel, a dot if it isn't selected, nothing if Master is selected — Master has no outgoing routes). The whole strip selects itself on click (`mixerStore.selectChannel`, both variants — Master is selectable too, just never becomes the *source* of a route). Takes the live `MixerChannelData`/`MasterChannelData` object by reference and mutates it directly in the template (same convention as `ChannelRow` and `channel.volume`) — see "Mixer"
        MixerRoutePoint.svelte — the click-to-route control: `kind: 'arrow' | 'dot'`, `active`, `disabled`, `onClick`. Its click handler always `stopPropagation()`s so clicking it never also re-selects the strip it sits on
        MixerFxRack.svelte     — right-column FX panel, fixed 190px width. No selector of its own — mirrors `mixerStore.selectedEntity` (channel or Master) and renders `MixerInsertSlots` for whichever is currently selected, with an empty-state message when nothing is (only reachable once every channel's been deleted)
        MixerInsertSlots.svelte — `{slots}` wrapper rendering a scrollable stack of `MixerInsertSlot` rows that fills the FX rack's available height
        MixerInsertSlot.svelte — one insert-slot row: index + "Empty" label + bypass toggle dot bound to `slot.enabled`. UI-only placeholder, no DSP — there's no plugin system in this app
        MixerMuteSolo.svelte   — mute (circle) + solo (square) button pair for a channel strip, mutating `data.muted`/`data.soloed` directly
        PeakMeterVertical.svelte — real per-track vertical peak meter (dB-scaled via `meterMath.ts`, same algorithm as the toolbar's `PeakMeter.svelte`). Takes a `trackId` prop and resolves its `AnalyserNode`(s) from `audioEngine` fresh every rAF frame (`getTrackAnalyser(trackId)` for a channel, `getStereoAnalysers()` for Master) rather than a static analyser prop, so it self-heals once `mixerAudio.svelte.ts` creates the track's chain even if that happens after this component mounts
```
