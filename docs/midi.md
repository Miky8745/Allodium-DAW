# MIDI

> Split out of `CLAUDE.md` to keep it under the size limit. Cross-references like "see X" name a section either in `CLAUDE.md` or in another `docs/*.md` file.


**Runs in Rust (`midir`, ALSA backend), not Web MIDI** — WebKitGTK has no Web MIDI API.

- **Port keys** — midir/ALSA port names end with `client:port` numbers (`"KeyLab:KeyLab MIDI 1 24:0"`) that change across replugs, so `midi.rs`'s `port_key()` strips them; duplicates get ` #2`/` #3`. The key is the identity everywhere (prefs, events, channel `midiOutPort`). The app's own ports (client name `Allodium`) are filtered out.
- **Backend threads** (`midi::start_threads`, from `lib.rs`'s `setup`): a hot-plug poller (every 2s; drops connections whose port disappeared, emits `midi-ports-changed` with a full `MidiPorts` when anything changed) and a scheduler (`BinaryHeap` + `Condvar`) for `midi_schedule`. Input callbacks emit `midi-message { port, bytes }`; clock/active-sensing are ignored at the midir level. `Inner::send()` tracks sounding notes per output so `midi_stop_all` can release notes whose queued note-off it just cancelled.
- **Reconnect-by-name** — `midiSystem.svelte.ts` re-applies `midi_set_inputs/outputs` (the enabled names from prefs) on start, on every `midi-ports-changed`, and whenever the enabled lists change. Since the poller dropped the dead connection, a replugged device reconnects automatically with its remembered settings. Disabling an input releases its held notes.
- **Input processing** (`midiProcessing.ts`, pure; per device, `MidiInputPrefs`): channel filter (omni/1–16) → key range (on the *incoming* key, i.e. a keyboard split) → transpose → velocity (fixed override, else curve exponent linear 1 / soft 0.6 / hard 1.6 / custom, + offset, clamped to min/max). `midiSystem` remembers which processed pitch each `port:channel:note` started so the note-off releases the same pitch even if transpose changed mid-hold. Only note on/off and pitch bend do anything; CC/program/etc. are just logged + blink the LEDs (future MIDI learn).
- **Pitch bend (live only)** — `processPitchBend()` (`midiProcessing.ts`, same channel filter as notes) maps the 14-bit value to ±`MidiInputPrefs.bendRange` semitones (default 2, Preferences › MIDI input row; Rust `bend_range`, `#[serde(default)]`). `liveNotes.pitchBend(source, semis)` keeps one bend per *source* (not per voice), applies it to every voice that source holds via `audioEngine.setLiveVoiceBend()` (`playbackRate = baseRate × 2^(bend/12)`, `setTargetAtTime` with `BEND_SMOOTHING` 8ms), and passes it to `startLiveVoice()` so a key struck with the wheel already deflected starts bent. `releaseSource`/`releaseAll` forget the bend (an unplugged device can't send the re-center). Rate changes pitch *and* speed (sampler behavior). Not recorded into the piano roll and not sent to MIDI out.
- **Live notes** (`liveNotes.svelte.ts`) — the one pipeline for all real-time sources (each hardware port, and `'Typing keyboard'`), keyed per (source, pitch). Plays `channelStore.selectedChannel` (fallback: first channel) via `audioEngine.startLiveVoice()`/`releaseLiveVoice()`: attack→decay→open-ended sustain until note-off, through the channel's mixer track, **ignoring Channel Rack mute/solo** (mixer-track mute still applies, it's in the graph). The voice id is returned synchronously so a note-off can't race a still-loading sample. `liveNotes.active` gates sound to the project view (set in `openProject`/cleared in `exitProject`); `held` (`SvelteMap<pitch, velocity 0..1>`) updates regardless. This is the hook point for future MIDI recording.
- **Glow** — `PianoRoll.svelte` passes `liveNotes.held` as `midiPitches` to `PianoKeys` (`.midi-glow` overlay — full row for white keys, inside `.black-key` for black ones — opacity/bloom scale with `--glow` = velocity) and to `NoteGrid` (faint full-width `.midi-row-glow`). Toolbar row 2's `MidiLed` blinks on any in/out message.
- **QWERTY keyboard** (`qwertyKeyboard.svelte.ts` + `QwertyPiano.svelte`) — the Toolbar's "Typing keyboard to piano" toggle (state moved out of `Toolbar.svelte`). Tracker-style layout by `KeyboardEvent.code`: `Z S X D C V G B H N J M` = C5..B5, `Q 2 W 3 E R 5 T 6 Y 7 U I` = C6..C7; `,`/`.` shift octave. Ignores repeats, modifier combos (Ctrl+Z etc. keep working), typing targets, and everything while Preferences is open. Releases all on window blur.
- **Output** — only **piano-roll notes**, never step-sequencer hits: `audioEngine`'s `NoteSink` (`setNoteSink`) is called from `scheduleChannelStep`'s notes branch (after the mute/solo check, so muted channels don't send) and from `previewNote`. `midiOutput.ts`'s `sendNote` skips unless `channel.midiOutPort` is an *enabled* output, converts AudioContext `playTime` to a wall-clock delay (`+ outputLatency` + the port's `latencyMs`), applies the port's transpose/velocity scale, and batches note-on/off pairs into one `midi_schedule` per microtask. A channel with a MIDI out but no sample still sends (for driving a hardware synth). `audioEngine.stop()` calls the stop hook (`setStopHook` → `midiOutput.stopAll` → `midi_stop_all`) only when a transport was actually running (song-end leaves queued note-offs to drain naturally).
- **Per-channel routing** — `ChannelData.midiOutPort: string | null` + `midiOutChannel: number` (1–16), set via ChannelRow's right-click › "MIDI out…" (`ChannelMidiOutMenu.svelte`), saved in `.alp` (`ChannelSettings.midi_out_port`/`midi_out_channel`, `#[serde(default)]`; `importState` normalizes `|| null`/`|| 1`). The sample still plays locally too.
- **Preferences › MIDI tab** — inputs/outputs lists (detected ports ∪ remembered ones, with connected/unplugged status + activity dot + enable switch); click a row for its settings; Rescan; monitor (last 100 messages, `midiStore.log`; inbound lines are raw/pre-processing, outbound are what was sent).
